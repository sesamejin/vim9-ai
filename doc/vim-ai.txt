INTRODUCTION                                    *vim-ai*

This plugin can be used to generate code, edit text, brainstorm ideas,
translate, etc.

The plugin is written in |vim9script| and requires Vim 9.1.0980 or newer
(it relies on |base64_encode()| and |base64_decode()|).
Neovim does not implement vim9script and is not supported.

All HTTP requests are made with the external `curl` command, the location can
be changed with |g:vim_ai_curl_path|.  Request headers, including the api key,
are passed to `curl` through a temporary config file with owner-only
permissions instead of the command line, so the token does not appear in the
process list.  The file is removed when the request finishes.

                                                *g:vim_ai_curl_path*
Location of the `curl` command used for the requests.  Either a path or a list
with a command prefix, for example `['wsl', 'curl']`.  Default: `'curl'`

INCLUDE FILES                                  *vim-ai-include*

To include files in the chat a special `include` role is used: >

  >>> user

  Generate documentation for the following files

  >>> include

  /home/user/myproject/requirements.txt
  /home/user/myproject/**/*.py

Each file's contents will be added to an additional `user` role message with
the files separated by `==> {path} <==`, where path is the path to the file.
Globbing is expanded out via `glob.gob` and relative paths to the current
working directory (as determined by `getcwd()`) will be resolved to absolute
paths.

ACP PROVIDER                                    *vim-ai-acp*

Besides the OpenAI compatible HTTP API the plugin can drive an ACP agent
(https://agentclientprotocol.com).  The agent is started as a subprocess and
the prompt is sent over JSON-RPC, so the agent reads and edits the project
itself instead of only returning text.

To use it, set the provider and the command of the agent: >

  let g:vim_ai_chat = {
  \  "provider": "acp",
  \  "options": {
  \    "agent_command": ["claude-code-acp"],
  \  },
  \}

The same works per chat buffer, in its header: >

  [chat]
  provider=acp
  options.agent_command=["npx", "-y", "@zed-industries/claude-code-acp"]

or with a role, e.g. `:AIChat /claude`.

An agent is started once per chat buffer and the buffer continues its session,
so only the new message is sent on every turn.  `:AI` and `:AIEdit` do not
reuse sessions, they send the whole conversation as one prompt and stop the
agent afterwards.  Tool calls, plans and notices are shown in the chat buffer
as `<<< info` sections.

The agent may ask for permission before it runs a tool.  The plugin serves
`fs/read_text_file` and `fs/write_text_file` and reloads buffers that show a
file the agent changed (buffers with local changes are left alone).

                                               *g:vim_ai_acp_chat*
Options of the acp provider, the complete and edit variants
(`g:vim_ai_acp_complete`, `g:vim_ai_acp_edit`) use `reuse_session = 0` and
`request_timeout = 120`:

  agent_command         command of the agent, a list or a string.
                        Default: `['claude-code-acp']`
  cwd                   working directory of the agent, empty means the
                        directory of the current buffer. Default: `''`
  session_key           empty means one session per buffer. Default: `''`
  permission_mode       `ask` shows a |confirm()| dialog, `allow` selects the
                        first allow option, `deny` the first reject option.
                        Default: `'ask'`
  enable_fs             1 serves `fs/read_text_file` and `fs/write_text_file`.
                        Default: `1`
  reuse_session         1 continues the agent session in the same buffer.
                        Default: `1` (chat), `0` (complete, edit)
  send_system_prompt    1 includes `>>> system` sections in the prompt.
                        Default: `1`
  request_timeout       seconds without any message from the agent before the
                        turn is given up, 0 disables the check. Default: `300`
  protocol_version      ACP protocol version. Default: `1`
  mcp_servers           MCP servers handed to `session/new`. Default: `[]`
  auth_method           method id of `authenticate`, empty skips the step.
                        Default: `''`

In an INI file `agent_command` and `mcp_servers` are written as json, a role
can switch the provider as well: >

  [claude]
  provider = acp
  options.agent_command = ["npx", "-y", "@zed-industries/claude-code-acp"]
  options.permission_mode = allow

`:AIImage` is not supported by this provider, it needs a model that generates
images.

CONFIGURATION                                   *vim-ai-config*

To customize the default configuration, initialize the config variable with
a selection of options: >

  let g:vim_ai_chat = {
  \  "options": {
  \    "model": "gpt-6.1-sol",
  \    "temperature": 0.2,
  \  },
  \}

Alternatively you can use special `default` role: >

  [default.chat]
  options.model=gpt-4
  options.temperature=0.2

You can also customize the options in the chat header: >

  [chat]
  options.model=gpt-4
  options.temperature=0.2

  >>> user

  generate a paragraph of lorem ipsum
  ...

ROLES

Roles are defined in the `.ini` file: >

    let g:vim_ai_roles_config_file = '/path/to/my/roles.ini'

Example of a role: >

    [grammar]
    prompt = fix spelling and grammar
    options.temperature = 0.4

Now you can select text and run it with command `:AIEdit /grammar`.
See roles-example.ini for more examples.

The roles in g:vim_ai_roles_config_file are converted to a Vim dictionary whose
labels are the names of the roles. Optionally, roles can be added by setting
g:vim_ai_roles_config_function to the name of a Vimscript function returning a
dictionary of the same format as g:vim_ai_roles_config_file.  The function
must be global, define it in your vimrc.  Values from the function take
precedence over the same section in g:vim_ai_roles_config_file.

MARKDOWN HIGHLIGHTING                            *g:vim_ai_chat_markdown*

Set g:vim_ai_chat_markdown = 1 to enable full markdown highlighting in aichat files.
Highlighting may be corrupted when using the preservim/vim-markdown plugin.

KEY BINDINGS

Examples how configure key bindings and customize commands: >

  " complete text on the current line or in visual selection
  nnoremap <leader>a :AI<CR>
  xnoremap <leader>a :AI<CR>

  " edit text with custom context
  xnoremap <leader>s :AIEdit fix grammar and spelling<CR>
  nnoremap <leader>s :AIEdit fix grammar and spelling<CR>

  " trigger chat
  xnoremap <leader>c :AIChat<CR>
  nnoremap <leader>c :AIChat<CR>

  " redo last AI command
  nnoremap <leader>r :AIRedo<CR>

CUSTOM COMMANDS

To create custom commands, call `AIRun`, `AIEditRun` and `AIChatRun` functions: >

  " custom command suggesting git commit message, takes no arguments
  function! AIPromptCommitMessageFn()
    let l:range = 0
    let l:diff = system('git diff --staged')
    let l:prompt = "generate a short commit message from the diff below:\n" . l:diff
    let l:config = {
    \  "options": {
    \    "model": "gpt-6.1-sol",
    \    "initial_prompt": ">>> system\nyou are a code assistant",
    \    "temperature": 1,
    \  },
    \}
    call vim_ai#AIRun(l:range, l:config, l:prompt)
  endfunction
  command! AIPromptCommitMessage call AIPromptCommitMessageFn(range)

  " custom command that provides a code review for selected code block
  function! AIPromptCodeReviewFn() range
    let l:prompt = "programming syntax is " . &filetype . ", review the code below"
    let l:config = {
    \  "options": {
    \    "initial_prompt": ">>> system\nyou are a clean code expert",
    \  },
    \}
    call vim_ai#AIChatRun(a:range, l:config, l:prompt, a:firstline, a:lastline)
  endfunction
  command! -range=0 AIPromptCodeReview <line1>,<line2>call AIPromptCodeReviewFn()

The run functions take the region lines as optional trailing arguments
({prompt}, {line1}, {line2}).  When they are omitted the visual selection is
used.  A range can also be passed directly from a command definition: >

  command! -range -nargs=? AIPromptCodeReview
    \ call vim_ai#AIChatRun(<range>, {}, 'review the code below', <line1>, <line2>)
